# Zinc v0.11.0

Schema v4 and its consumers: `zc`, `zcr`, `zvr`, `zlt`, and `zlg`.
This is a breaking pre-1.0 minor release, including changes to runtime setup.

## Upgrade requirements

- Preserve existing app definitions and VM runtime data before editing them.
  Representable v3 and earlier v4 fields migrate in memory before strict decoding.
  Conflicts and removed settings without a lossless translation are errors;
  loading a definition does not rewrite it or reset guest storage.
- Networking now requires owner-provisioned packet-preserving namespaces/TAPs
  and matching manifests. Zinc no longer creates pasta uplinks, sibling routes,
  or WireGuard tunnels automatically. Empty `Interfaces` means no managed NIC.
- PipeWire grants require explicit deployment of Zinc's WirePlumber policy.
  Missing policy or selected devices aborts audio preparation. Host audio services
  are not installed or restarted by an app launch.
- VM disk pins, sizes, hardware profiles, installation media, and port mappings
  use `$XDG_CONFIG_HOME/zinc/runtime/vm/<app>.json` or explicit runtime options.
  Base-image verification remains mandatory; existing disks are preserved.
- Source builds require Go 1.26. The Podman pipeline pins Go 1.26.6 by image
  digest; the existing Nix lock supplies Go 1.26.5 through `buildGo126Module`.

See [migration](../migration.md), [network provisioning](../network-provisioning.md),
[WirePlumber deployment](../../integration/wireplumber/README.md), and
[VM runtime options](../virtualization.md).

## Highlights

- Presentation fields live in `LauncherMeta`. Both runtimes use shared resource,
  display, image, and lifecycle fields where they can enforce their meaning.
- Initial and attached commands have separate environment maps. Autorestart
  lives under `StopConditions`; read-only rootfs under `StartConditions`.
- Ordered `From`/`To` network rules apply source/destination address and port
  filters, first-match/default-deny decisions, and both app endpoints' permission.
  Public-only `Internet` is distinct from host, app, and private destinations.
- DNS supports UDP, TCP, authenticated TLS, HTTPS, and QUIC, with explicit
  bootstrap addresses, configured fallback, and authenticated proxy readiness.
  Both runners expose `dns-proxy`.
- Audio has additive default/named PipeWire and exact ALSA selections. Private
  endpoints separate playback, microphone, and host-monitor access.
- Raw `CreatorFlags` and `RunnerFlags` preserve argv elements and warn that they
  can override Zinc's managed isolation and lifecycle guarantees.
- VM supervision handles process crashes, manual-stop suppression, helper
  cleanup, and a separate preparation deadline. Read-only VM drives are enforced.
- Launchers select the correct runtime and retain container instance addresses.
  Creator CLI/TUI, Compose conversion, examples, vendors, and Nix consumers use
  the canonical schema. The Nix `runtime-integration` output packages setup files.

## Fixes included

- Failed network device preflight closes stale permissions before returning.
- Rootless namespace attachment avoids re-entering Podman's current user namespace.
- Counter helpers join the verified running namespace correctly.
- Inheritance preserves numeric-looking strings and bounds alias expansion.
- File-launched containers hand their resolved configuration to the supervisor.
- TUI builds accept creator flags without install steps.

## Verification and supported scope

Release preparation exercises all eight module checks and vendor checks, five
reproducible tool builds, DNS transport/race tests, 256 live packet assertions,
nine isolated audio tests, container E2E, offline VM lifecycle, and positive
provisioned container/TAP launch-cleanup-relaunch paths.

The broad container network scenario needs separately provisioned fixtures and
reports a skip when they are absent; isolated packet and production attachment
suites test those boundaries separately. VM smoke/provisioning tests use TCG
and a blank disk, not a full guest OS boot or a KVM compatibility certification.
Physical audio devices and the active desktop session are not exercised.

Guest-side commands, environments, filesystem/bus bridges, graphical VM
Background behavior, and unresolved ALSA monitor routes remain explicit errors.
Domain rules are frozen IP snapshots rather than hostname inspection. Raw backend
arguments opt out of typed guarantees. These limits are detailed in the
[architecture reference](../architecture.md).

## Artifacts and publication

Linux AMD64 candidates contain `zc-linux-amd64`, `zcr-linux-amd64`,
`zvr-linux-amd64`, `zlt-linux-amd64`, `zlg-linux-amd64`, and `SHA256SUMS`.
Every binary must report exactly its tool name followed by `v0.11.0`.

Local candidate files are verification outputs. Publication follows reviewed
`dev -> release/0.11.0 -> main` PRs and a signed `v0.11.0` tag. CI rebuilds the
tagged source, generates checksums, and publishes only after asset verification.
